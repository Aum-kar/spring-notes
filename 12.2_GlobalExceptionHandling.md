# Global Exception Handling in Spring Boot

## Purpose

Global exception handling allows us to:

* Centralize error handling logic
* Avoid try-catch blocks in controllers
* Return consistent and structured error responses
* Separate business logic from error formatting

---

## Basic Flow of Exception Handling

Example: Client requests a product that does not exist.

### Step 1 — Controller Calls Service

```java
@GetMapping("/{id}")
public ProductResponse getProduct(@PathVariable Long id) {
    return productService.getProduct(id);
}
```

---

### Step 2 — Service Throws Exception

```java
public ProductResponse getProduct(Long id) {
    Product product = productRepository.findById(id)
            .orElseThrow(() -> new ProductNotFoundException(id));

    return mapToResponse(product);
}
```

If the product is not found, `ProductNotFoundException` is thrown.

---

### Step 3 — Spring Intercepts the Exception

Spring searches for a matching method annotated with `@ExceptionHandler`.

If found, it calls that method.

---

### Step 4 — Global Handler Builds Response

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ProductNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handleProductNotFound(
            ProductNotFoundException exception
    ) {

        Map<String, Object> response = new HashMap<>();
        response.put("timestamp", LocalDateTime.now());
        response.put("status", 404);
        response.put("message", exception.getMessage());

        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(response);
    }
}
```

---

### Step 5 — Response Sent to Client

Client receives:

```json
{
  "timestamp": "2026-02-20T09:25:22.5644306",
  "status": 404,
  "message": "Product with id 1000 not found"
}
```

The controller method does not continue execution.
The exception is fully handled by the global handler.

---

## What is `@RestControllerAdvice`?

`@RestControllerAdvice` is used on classes.

It marks the class as a global exception handler for all controllers.

It is a combination of:

* `@ControllerAdvice`
* `@ResponseBody`

Meaning:

* It applies to all controllers.
* It automatically converts returned objects into JSON responses.

Syntax:

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
}
```

---

## What is `@ExceptionHandler`?

`@ExceptionHandler` is used on methods inside a `@RestControllerAdvice` class.

It tells Spring:

"If this type of exception is thrown, execute this method."

Syntax:

```java
@ExceptionHandler(ProductNotFoundException.class)
public ResponseEntity<?> handleProductNotFound(ProductNotFoundException ex) {
    // build and return response
}
```

You can also handle multiple exceptions:

```java
@ExceptionHandler({ProductNotFoundException.class, OrderNotFoundException.class})
```

---

## How Exception Handling Works Internally

1. Controller method executes.
2. Service throws an exception.
3. Spring looks for a matching `@ExceptionHandler`.
4. Matching handler method runs.
5. Handler returns a `ResponseEntity`.
6. Client receives structured JSON response.

---

## Important Points

* Controllers should not contain try-catch for business exceptions.
* Services throw exceptions.
* Global handler formats responses.
* `RuntimeException` causes transaction rollback by default.
* Validation exceptions (like `MethodArgumentNotValidException`) are thrown automatically by Spring when `@Valid` fails.

---

## Summary

* Custom exceptions represent domain or resource errors.
* `@RestControllerAdvice` is used at class level.
* `@ExceptionHandler` is used at method level.
* Exceptions propagate from service to global handler.
* Global handler builds consistent API error responses.
