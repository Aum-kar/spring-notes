# Spring Security Basics

- When we add `spring-boot-starter-security` dependency, it protects all the endpoints using basic auth.
- For web browsers, it provides a basic login form with username and password.
- When user logs in successfully, server assigns a cookie. When you send a request, browser/host adds `Cookie: JSESSIONID=<token>` in request header which server authenticates.
- If you are using non-browser client (like postman or .http), then you can send credentials as either `Authorization: Basic <username> <password>` or `Authorization: Basic base64(username:password)`

### Basic flow of our CRUD APIs after adding Spring boot security

- Initially after receiving a request we were doing: validate request body > Controller > Service > Repository > Database
- But now, we have added a security layer on top of it, so our current flow is Validatation and Authorization of user > validate request body > ...
- The spring security itself uses some default configurations like providing basic login form, using basic authentication, using session based stateful authentication.
- We can change these behavior by configuring `SecurityFilterChain`, below is a simple example.

#### Example of Security Configuration

```java
@Configuration
public class SecurityConfig {
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity httpSecurity) {

        httpSecurity.formLogin(form -> form.disable()); // disables built-in login page
        httpSecurity.csrf(csrf -> csrf.disable());      // usually done in stateless auth

        return httpSecurity.build();
    }
}
```

### Before you learn Spring Security, make sure to understand below concepts

1. Difference in 'encoding', 'encrypting' and 'hashing' the data.
    - Encoding: We convert our data into some strings that can be sent easily via network. It is easier to decode the text. Example is base64 encoding.
    - Encrypting: We change the data into something that is unrecongnization, an encrypted data can be decrypted by a key. So, it is bi-directional.
    - Hashing: We convert password data into hashes. It cannot be reverted to original text, but we can compare for equality with other hash.

2. Stateful authentication vs Stateless authentication.
    - Stateful: Uses Sessions and Cookies, default spring authentication method.
    - Stateless: Server does not store any session.

3. Difference in Authentication and Authorization
    - Authentication: If client is valid or not.
    - Authorization: If client is allowed to access data.

4. CSRF token - It protects POST, PUT & DELETE requests
